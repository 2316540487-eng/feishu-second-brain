## 📋 窝窝选股逻辑 v4.0

用户整理完成一套完整的短线选股体系，核心框架：

```
第 0 步：消息面 → 第 1 步：大环境 → 第 2 步：找主线 → 第 3 步：定龙头 → 第 4 步：炸板评分 → 第 5 步：入场条件
```

**核心亮点：**
- 消息面分级 + 仓位挂钩（S/A/B/C 级对应不同仓位上限）
- 炸板风险评分量化（≤30 推荐 | 31-50 谨慎 | >50 不碰）
- 五条铁律（封单量是纸老虎、烂板是好事、一字板 + 缩量加速不碰等）

**待优化点（已反馈给用户）：**
1. 大环境阈值需动态调整（注册制后连板生态变化）
2. 炸板评分的换手维度需细化（量比、换手率绝对值、分时分布）
3. 入场条件缺少时间维度（10:00 前/10-14:00/14:00 后封板质量不同）
4. 仓位管理可增加个人状态维度（连续亏损/盈利后的调整）
5. 缺少止盈规则细化
6. "主线"定义可能滞后，需增加早期信号

## 🔧 OpenClaw 配置常见问题

**问题场景：** 修改 `openclaw.json` 后 Gateway 启动失败

**常见错误及解决：**

### 1. mode 字段值不合法
```json
// ❌ 错误：把 API Key 填到 mode 字段
"mode": "sk-37bf5b8635f94a4a9807271f8addaae6"

// ✅ 正确
"mode": "api_key",
"apiKey": "sk-37bf5b8635f94a4a9807271f8addaae6"
```

允许值：`"api_key"` | `"oauth"` | `"token"`

### 2. JSON 逗号错误
```json
// ❌ 错误：对象最后一个属性后面多逗号
"apiKey": "sk-xxx",
}

// ✅ 正确
"apiKey": "sk-xxx"
}
```

### 3. 多余字符
```json
// ❌ 错误：多了 []
[]"mode": "oauth"

// ✅ 正确
"mode": "oauth"
```

**修复命令：**
```bash
# 自动修复配置
openclaw doctor --fix

# 重新生成配置
openclaw configure

# 重启验证
openclaw gateway restart
openclaw gateway status
```

**注意事项：**
- 确认编辑的是当前用户配置文件（`~/.openclaw/openclaw.json`）
- 保存时看到 "Wrote X lines" 才算成功
- 多用户环境下注意文件路径（如 `/Users/chenming/` vs `/Users/yy/`）
